# Ransom0 테스트 엔진 사용법

`Ransom0-TestLab.zip`을 새 폴더에 풀고 `Start-TestLab.cmd`를 관리자 권한으로 실행합니다. 메뉴 번호를 입력한 다음 영문 대문자 `TEST`를 입력합니다. Ransom0가 설치된 시험 VM에서 사용하며 별도 Python 설치는 필요 없습니다.

| 번호 | 시험 | 확인하는 내용 |
|---|---|---|
| 1 | 30초 대기 | 추가 부하 없는 상태의 유실 증가 |
| 2 | 파일 쓰기 12,000회 | 짧은 집중 부하에서 수집·유실 |
| 3 | 파일 쓰기 120,000회 | 높은 부하에서 수집 한계; 유실 가능 |
| 4 | 저장·이름/확장자 변경 1,000회 | 파일 이벤트 처리 |
| 5 | 프로세스 50개 순차 실행·종료 | 프로세스 이벤트 처리 |
| 6 | 시험 문서 준비 | 전용 폴더와 문서 12개 생성 |
| 7 | VSS 복구 및 SHA256 비교 | 변경한 시험 파일의 원상 복구; 자동 탐지 시험과 별개 |
| 8 | Track A 자동 대응 | 규칙과 행위 교차 확인 후 차단·종료·복구 |
| 9 | Track B 실제 JEV 판정 | 시험 수치를 실제 JEV로 전송하고 판정에 따른 대응 확인 |
| 10 | 기본 시험 묶음 | 1 → 2 → 4 → 5 순서; 실패·판단 불가 시 중단 |
| 11 | 커널 Rule1001 생성 차단 | 무해한 WHERE 복사본 사용, JEV 미사용; 전체 복구 시험과 별개 |
| 0 | 종료 | 메뉴 종료 |

## 복구·자동 대응 시험 준비

1. 6번을 실행합니다.
2. Ransom0 설정에서 `C:\ProgramData\Ransom0TestLab\Protected`를 복구 범위로 적용합니다.
3. 7번으로 복구를 확인합니다. 8·9번은 제품의 자동 대응 준비를 완료한 뒤 실행합니다. 현재 제품 설정은 API 키 준비도 요구하며, Track A 판단 자체는 JEV 점수를 사용하지 않습니다.
4. 9번은 실제 JEV 요청 및 호출 비용이 발생할 수 있습니다. 정상·보류 판정을 강제로 악성으로 바꾸지 않습니다.

12개는 시험 자료 수이며 제품의 최소 파일 수가 아닙니다. 실제 사용자 문서 폴더는 시험에 사용하지 않습니다. 8·9번은 VM 전체 인터넷을 격리할 수 있으며 검토 보류는 임의로 해제하지 않습니다. 실제 랜섬웨어나 VSS 삭제 도구를 실행하지 않습니다.

## 결과 읽기

결과는 `C:\ProgramData\Ransom0TestLab\Runs\실행ID`의 `report.txt`와 `report.json`에 저장됩니다.

- PASS: 해당 시험의 확인 조건 충족
- FAIL: 유실·큐 비움 또는 검증 실패
- INCONCLUSIVE: 조건이나 증거 부족으로 판단 불가
- ERROR: 실행 오류 또는 준비 부족

카운터와 기존 기록은 초기화하지 않습니다. 3번은 실사용 평균 부하가 아니며 이전 시험에서 유실이 발생했습니다. PASS는 모든 부하에서 유실 0이나 모든 랜섬웨어 탐지를 보장하지 않습니다. 시험 결과의 영문 상태 코드와 원본 진단 JSON은 그대로 유지합니다.

이번 변경은 메뉴·안내 한글화입니다. VM 부하·차단·복구 시험을 다시 실행한 변경이 아닙니다. 통합 설치본 재설치 없이 TestLab ZIP만 교체하면 됩니다.
