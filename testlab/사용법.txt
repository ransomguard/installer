Ransom0가 설치된 시험용 Windows VM에서 이 폴더를 풀고 Start-TestLab.cmd를 관리자 권한으로 실행합니다. 별도 Python 설치나 ChatGPT가 필요 없습니다. 실행할 항목을 선택하고 TEST를 입력합니다.

1. 유휴 30초: 아무 부하 없이 유실 증가 여부 확인
2. 쓰기 12,000회: 짧은 쓰기 집중 부하
3. 쓰기 120,000회: 더 큰 순간 부하 (실사용 평균을 뜻하지 않음)
4. 저장/확장자 변경 1,000회: 정상 저장과 이름 변경 반복
5. 프로세스 50개: 순차 생성·정상 종료
6. 복구 시험 문서 준비: C:\ProgramData\Ransom0TestLab\Protected 아래 자체 문서 12개만 생성
7. VSS 복구: 설정에서 위 시험 폴더를 보호 범위로 선택한 뒤 실행. 실제 스냅샷을 만들고 자체 문서만 변경한 후 제품 복구 엔진으로 되돌려 SHA256 비교. 자동 악성 판정·차단 시험과는 별개입니다.
8. Track A: 시험 폴더와 API 키 설정으로 자동 대응을 준비한 뒤 실행. 자체 문서에 한정된 무해한 고엔트로피 쓰기와 Windows where.exe의 이름을 바꾼 복사본으로 생성 차단 규칙을 자극합니다. 진짜 VSS 삭제 도구를 실행하지 않습니다.
9. Track B: 같은 준비 후 실제 JEV로 시험 행위 수치를 보내는 경로를 실행합니다. JEV 호출 비용은 별도 발생할 수 있습니다. 점수를 조작하지 않으며 정상·보류 판정이나 조건 불충족이면 차단 성공으로 처리하지 않습니다.

결과: C:\ProgramData\Ransom0TestLab\Runs\실행ID\report.txt 및 report.json
PASS=해당 시험 항목의 확인 조건 충족, FAIL=유실/큐 비움 또는 복구 검증 실패, INCONCLUSIVE=아직 조건·증거 불충분, ERROR=실행 오류/준비 불충분.
최종 PASS도 모든 랜섬웨어 탐지율이나 모든 부하의 유실 0을 의미하지 않습니다. 프로세스 정상 종료나 시험 도구가 직접 정리한 종료는 제품의 강제 종료 성공으로 세지 않습니다.

시험 범위와 보존:
- 일반 부하는 도구가 만든 실행별 폴더만 사용합니다. 실제 사용자 문서를 순회하거나 암호화하지 않습니다.
- 복구/A/B는 정확히 위 전용 보호 폴더만 허용합니다. 기존 보호 범위를 자동 변경하지 않습니다. 사용자 문서가 섞이면 거부합니다.
- 실행 전 VM 스냅샷을 권장합니다. A/B 자동 대응으로 VM 전체 인터넷이 격리될 수 있습니다. 복구·검토 보류를 임의 해제하지 않습니다.
- 실패한 문서는 자동으로 정상인 척 덮어쓰지 않습니다. 다음 A/B 실행 전에 제품에서 복구하고 해시를 확인해야 합니다.
- 카운터와 기존 기록은 초기화하지 않습니다. 보고서는 실행 전후 차이를 사용합니다. 수집기 재시작/카운터 감소가 있으면 유효한 비교로 처리하지 않습니다.
- 8·9번만으로는 실제 네트워크 접속 허용·차단을 증명하지 않습니다. 12번은 두 대상의 IPv4 TCP/HTTPS 443번 새 연결을 별도로 확인합니다.
- Ctrl+C로 중단한 시험은 완료된 검증이 아닙니다. A/B 도중 중단해도 기존 방화벽 hold를 해제하지 않습니다.

10번 자동 기본 묶음은 유휴 → 12,000회 쓰기 → 저장/이름 변경 → 프로세스 생성을 순서대로 실행합니다. 실패·증거 불충분·오류가 나오면 중단하며, 실제 JEV/차단/복구는 이 묶음에 포함하지 않습니다.

11번 커널 생성 차단은 JEV 없이 시험할 수 있습니다. 무해한 where.exe 복사본과 실제 커널 차단 이벤트를 대조합니다. 실제 VSS 삭제는 하지 않습니다. 부모 강제 종료·자동 복구 전체 검증과는 구분합니다.
