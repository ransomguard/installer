# Ransom0 Preview18

## 다운로드

- **설치:** [Ransom0-Install.zip](https://github.com/ransomguard/installer/releases/download/v0.6.0-preview.18/Ransom0-Install.zip) — 통합 설치 EXE·점검 도구·VM/호스트 시험 가이드.
- **시험:** [Ransom0-TestLab.zip](https://github.com/ransomguard/installer/releases/download/v0.6.0-preview.18/Ransom0-TestLab.zip) — 시험 실행기·사용법·검증 보고서.

ZIP을 풀고 가이드를 확인하세요. Source code 파일은 설치에 필요 없습니다. 내부 시험 서명판이며 일반 배포 서명판이 아닙니다. 설치 후 설정에서 자신의 JEV API 키와 복구 범위를 입력합니다. 평상시 네트워크 설정은 유지하며 위협 자동 대응 때 격리할 수 있습니다.

## 수정

- 파일 **1개**만 있어도 복구 범위를 적용할 수 있습니다. 파일 생성 전의 빈 스냅샷을 재사용하던 문제를 수정했습니다.
- 커널 콘솔의 실제 새 이벤트 전달, 대응 콘솔의 여러 생산자 연결, 대기 안내를 수정했습니다. 과거 기록 재생이나 가짜 보안 사건을 만들지 않습니다.
- 예약 백그라운드 작업의 불필요한 콘솔 창 노출을 줄였습니다.
- 업그레이드 시 필요한 콘솔 모듈을 함께 배치합니다.
- TestLab 메뉴 6번의 `prepare` 인자가 `p`로 잘리던 수정과 Rule1001 Track A 표시를 포함합니다.

## 검증

백엔드 512개·설치기 19개·TestLab 7개 시험 통과. Windows 11 VM 업그레이드 및 파일 1개 복구 범위 준비, 실제 VSS 파일/임시 복사본 SHA256 비교, 커널 새 이벤트 전달 및 동시 파이프 연결을 확인했습니다. 사용자 원본·기록·네트워크·계정 설정을 유지했으며 카운터를 초기화하지 않았습니다. 관찰 시 커널 유실/큐 비움은 0이었습니다.

이번 버전의 **신규 설치·재부팅, 실제 JEV 강제 종료·복구 전체 흐름, 물리 PC·다른 백신 공존은 검증 완료 항목이 아닙니다.** 콘솔의 실제 전송 경로는 검증했지만 모든 UI 버튼의 수동 클릭 검증은 별도입니다. 시험 중 실패와 복구 내역은 ZIP 검증결과에 기록했습니다.

## TestLab 복구 시험

6번은 전용 시험 폴더와 문서 12개를 만듭니다. 해당 폴더를 Ransom0 설정에서 복구 범위로 적용한 다음 7·8·9번을 사용합니다. **12개는 시험 도구 자료이며 제품의 최소 파일 수가 아닙니다.** 실제 사용자 문서 폴더에서 시험하지 마세요. JEV 점수와 차단·복구 성공을 조작하지 않습니다.

각 ZIP에 SHA256SUMS.txt가 있습니다.

VM 진단 에이전트 중지 전/후 각 30초 UI 기록은 289→48건(9.62→1.60건/초)이었습니다. 반복 VMware 조회를 중지했으며 제품 수집은 계속됐습니다. 정상 시스템 이벤트를 광범위하게 숨기는 필터를 추가하지 않았습니다.
