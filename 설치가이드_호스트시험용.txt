Ransom0 상세 설치 가이드 — 물리 PC(호스트) 내부 시험
기준: 0.6.0-preview.16 / 작성일: 2026-11-20

왜 사전 준비가 필요한가?
Ransom0는 Windows 커널 안에서 실행되는 드라이버를 사용합니다.
현재 드라이버는 시험 서명판입니다. 따라서 이 후보 설치본은 Secure Boot OFF와
시험 서명 허용이 사전에 준비된 환경에서만 설치하도록 검사합니다.
이는 랜섬웨어를 막기 위한 설정이 아니라 아직 정식 배포 서명이 없는 개발·시험 조건입니다.
Secure Boot는 부팅 구성요소의 신뢰성을 검사하며, 시험 모드는 시험 서명된 커널 코드의
로드를 허용합니다. 일반 사용 환경보다 신뢰 조건이 완화되므로 시험 환경에서 진행합니다.
향후 Microsoft 서명과 호환성 검증을 마친 배포판에서는 이 준비가 필요 없도록 해야 합니다.

이번 파일과 동작
- 버전: 0.6.0-preview.16. 같은 이름의 이전 preview 파일과 혼동하지 마세요.
- 파일: Ransom0-Setup.exe. VM과 물리 시험 PC에서 같은 파일을 사용합니다.
- 이 EXE에 필요한 구성요소가 포함돼 있어 GitHub에서 따로 모을 필요가 없습니다.
- 설치·업데이트는 기존 인터넷·Windows 방화벽·hosts 설정을 유지합니다.
- 자동 대응 조건을 만족한 사건에서 격리를 요청하며, 마지막 정상 해제 조건을 충족해야
  격리를 해제하고 이전 예외 목록을 복원합니다. 실패·검토 보류가 있으면 격리를 유지합니다.
- 기존에 차단된 인터넷을 설치기가 자동으로 열어주지는 않습니다.
- API 키·복구 폴더는 설치 후 설정에서 입력합니다. 로그인 암호는 변경하지 않습니다.
- 새 VM의 항목별 결과는 함께 제공하는 검증결과.txt를 확인하세요. 물리 PC 설치·제거 검증은 별도입니다.

읽는 방법
아래 명령은 한 줄씩 입력한 다음 Enter를 누릅니다.
'PS C:\WINDOWS\system32>' 같은 프롬프트나 예상 출력은 입력하지 않습니다.
예상 출력의 문구·대소문자는 Windows 언어에 따라 조금 다를 수 있습니다.
성공 조건을 확인한 뒤 다음 단계로 진행합니다. 오류가 나오면 해당 단계에서 멈춥니다.

1. 시험 PC와 복구 수단 준비
실제 Windows PC에 설치하는 절차입니다. VM 설정은 물리 PC에 영향을 주지 않습니다.
VM과 동일한 Ransom0-Setup.exe를 사용하지만 물리 PC의 보안 설정을 준비해야 합니다.
가능하면 초기화 가능한 별도 시험 PC를 사용하고 소유자·관리자의 시험 허가를 확보합니다.
학교 관리 정책으로 설정이 잠겨 있으면 우회하지 말고 관리자에게 준비를 요청합니다.
Windows x64, NTFS 시스템 드라이브, 설치용 최소 6GiB와 별도 스냅샷 여유 공간이 필요합니다.

① 중요한 자료를 다른 장치에 백업하고 Windows 복구 수단을 준비합니다.
   시스템 복원 지점만으로 모든 드라이버·펌웨어 변경이 복구된다고 가정하지 않습니다.
② 현재 인터넷 사용 여부와 Secure Boot·BitLocker 상태를 기록합니다.
③ 시작에서 'BitLocker 관리'를 검색하거나 설정의 '장치 암호화'를 확인합니다.
④ 켜져 있다면 복구 키를 다른 장치에서도 확인할 수 있게 보관합니다.
⑤ 부팅 설정을 바꾸기 직전에 BitLocker 보호를 일시 중단합니다.
   보호 일시 중단과 드라이브 암호 해제는 다릅니다. 메뉴가 없으면 먼저 확인을 받습니다.
⑥ 복구 키 확보와 복구 수단 준비가 끝난 뒤 다음 단계로 진행합니다.

2. 물리 PC의 Secure Boot OFF
① Windows 시작 → 설정 → 시스템 → 복구를 엽니다.
② '고급 시작 옵션'의 '지금 다시 시작'을 누릅니다. 열어둔 문서는 먼저 저장합니다.
③ 복구 화면에서 문제 해결 → 고급 옵션 → UEFI 펌웨어 설정 → 다시 시작을 선택합니다.
④ 제조사 펌웨어 화면에서 Security 또는 Boot 메뉴의 Secure Boot를 찾습니다.
⑤ Enabled에서 Disabled로 변경한 뒤 Save & Exit로 저장하고 부팅합니다.

제조사마다 메뉴 이름과 저장 키가 다릅니다. F10이 항상 저장 키라고 가정하지 않습니다.
화면에 표시된 도움말 또는 해당 모델의 제조사 안내를 확인합니다.
UEFI를 Legacy/CSM으로 바꾸지 말고, Secure Boot 키 삭제·TPM 초기화도 하지 않습니다.
Windows로 정상 부팅되는지 확인합니다. BitLocker 복구 화면이 나오면 보관한 키를 사용합니다.
UEFI 메뉴가 없거나 Secure Boot 변경이 잠겨 있으면 해당 PC 지원 여부를 먼저 확인합니다.

3. 시험 서명 설정 → 재부팅 → 결과 확인
설치할 물리 PC의 관리자 PowerShell에서 진행합니다.
시험 서명 설정 — 여기서는 아직 설치하지 않습니다
관리자 PowerShell에서 다음 한 줄을 입력하고 Enter를 누릅니다.

    bcdedit /set testsigning on

성공하면 입력한 명령 바로 다음 줄에 다음과 같은 메시지가 나옵니다.

    작업을 완료했습니다.

이 메시지는 '다음 부팅에 적용할 설정을 저장했다'는 뜻입니다.
지금 실행 중인 Windows에 적용됐다는 뜻은 아닙니다.

반드시 Windows를 재부팅합니다
① 열어둔 문서가 있으면 저장합니다.
② Windows 시작 버튼 → 전원 → '다시 시작'을 선택합니다.
③ Windows 바탕화면까지 다시 들어올 때까지 기다립니다.
   로그아웃·잠금·절전·VM 일시 중단은 재부팅이 아닙니다.
④ 재부팅 후 관리자 PowerShell에서 아래 확인 명령을 실행합니다.
   이미 명령을 실행하고 재부팅했다면 명령을 반복해서 설정할 필요는 없습니다.

재부팅 후 첫 번째 확인 — Secure Boot
아래 명령을 입력하고 Enter를 누릅니다.

    Confirm-SecureBootUEFI

정상 예시:

    PS C:\WINDOWS\system32> Confirm-SecureBootUEFI
    False
    PS C:\WINDOWS\system32>

볼 곳: 입력한 명령 바로 아래 한 줄의 'False'.
의미: Secure Boot가 꺼져 있습니다. 여기서 False는 실패가 아니라 원하는 결과입니다.
- True: Secure Boot가 켜져 있습니다. 앞의 Secure Boot 설정을 다시 확인합니다.
- 빨간 오류·지원되지 않음·권한 오류: False와 다릅니다. 설치를 진행하지 않습니다.

재부팅 후 두 번째 확인 — 시험 서명
다음 명령을 큰따옴표와 중괄호까지 그대로 입력하고 Enter를 누릅니다.

    bcdedit /enum "{current}"

정상 출력의 일부 예시:

    Windows 부팅 로더
    -------------------
    identifier              {current}
    description             Windows 11
    ...
    recoveryenabled         Yes
    testsigning             Yes
    isolatedcontext         Yes
    ...

볼 곳: 왼쪽 이름이 정확히 'testsigning'인 행 → 같은 행 오른쪽의 'Yes'.
'recoveryenabled Yes' 또는 'isolatedcontext Yes'를 보고 판단하면 안 됩니다.
화면에 안 보이면 마우스 휠로 출력 내용을 위아래로 살펴봅니다.
testsigning 행이 없거나 No라면 관리자 여부와 설정 성공 여부를 다시 확인합니다.

다음 단계로 넘어가는 조건
[ ] testsigning on 명령이 성공했다.
[ ] 그 명령 이후 Windows를 실제로 다시 시작했다.
[ ] 다시 연 관리자 PowerShell에서 Secure Boot 결과가 False다.
[ ] 부팅 로더 목록의 testsigning 행이 Yes다.

주의: 재부팅 전에도 bcdedit 목록에는 Yes가 보일 수 있습니다.
따라서 False·Yes만 확인하고 재부팅을 생략하면 안 됩니다.
바탕화면에 '테스트 모드' 글씨가 보일 수 있지만 워터마크만으로 판단하지 않습니다.

4. 물리 시험 PC에 설치
설치 자체는 인터넷을 차단하지 않습니다. 이후 위협 격리가 발동하면 원격 접속이
끊길 수 있으므로 시험·복구 작업을 직접 할 수 있는 상태에서 진행합니다.
기존 백신을 무조건 끄거나 제거하지 않습니다. 동시 동작 호환성은 별도 시험 대상입니다.
통합 설치 EXE 실행
① preview.12 폴더의 Ransom0-Setup.exe를 설치할 Windows의 로컬 디스크에 복사합니다.
② 파일을 더블클릭하고 관리자 승인 창에서 '예'를 누릅니다.
③ 'Ransom0 설치 및 관리' 창이 나타나는지 확인합니다.
   압축 해제 때문에 창이 뜨기까지 시간이 걸릴 수 있습니다. 여러 번 실행하지 마세요.
   열리지 않거나 오류 창이 나오면 그 문구를 기록합니다.
④ '승인된 시험 VM/PC입니다. 위협 자동 대응 시 PC 전체 네트워크 격리에 동의합니다.'
   항목을 읽고 체크합니다. 설치 직후 인터넷 차단에 동의하는 항목이 아닙니다.
⑤ '설치 / 업데이트' 버튼을 누릅니다.
⑥ 아래 로그 영역에서 설치 실행 결과와 '작업 완료'를 확인합니다.
   창을 처음 열었을 때 자동 상태 조회도 실행되므로, 이전 상태 조회의 '작업 완료'만
   보고 설치가 끝났다고 판단하지 않습니다. 설치 버튼을 누른 뒤의 결과를 확인합니다.
⑦ '작업을 완료하지 못했습니다' 또는 ERROR가 보이면 마지막 오류를 보존합니다.
⑧ 설치 성공 후 대시보드가 열리지 않으면 관리 창의 '실행'을 누릅니다.
   관리 창을 닫았다면 바탕화면에 생성된 'Ransom0' 바로가기로 관리 창을 열 수 있습니다.
   새 설치의 바로가기와 대시보드 제품명은 Ransom0입니다.

설치 직후 먼저 확인할 것
- 설치 전 인터넷이 됐다면 설치 직후에도 같은 연결을 사용할 수 있는지 확인합니다.
- 원래 인터넷이 없는 환경이라면 설치가 인터넷을 새로 만들어주지 않습니다.
- API 키와 복구 범위를 아직 입력하지 않았다면 '미등록/미지정' 표시는 정상입니다.
- 위협·복구 숫자가 0이어도 정상입니다. 시험하지 않은 위협 기록이 생겨야 하는 것은 아닙니다.
- 기존 preview.10이나 시험 정책으로 차단됐던 환경은 이번 설치로 자동 해제되지 않습니다.

Ransom0 최초 설정
① 대시보드 왼쪽 메뉴에서 '설정'을 누릅니다.
② '보호 설정' 탭을 선택합니다.
③ 'JEV (TypeSafe) API 키' 입력 칸에 자신의 키를 넣고 '키 저장'을 누릅니다.
   키·복구 키가 들어간 화면은 공유하지 마세요. 저장 성공은 서버 인증 성공과 다릅니다.
④ 파일 탐색기에서 문서 폴더 아래에 'Ransom0_시험문서' 같은 새 폴더를 만듭니다.
⑤ 메모장으로 '복구 전 원본입니다'라고 적고 그 폴더에 '복구시험.txt'로 저장합니다.
⑥ 보호·복구 범위의 '폴더 선택'을 누르고 방금 만든 폴더를 선택합니다.
⑦ 복구 시 파일 덮어쓰기에 관한 동의 항목을 읽고 체크합니다.
⑧ '복구 범위 적용'을 누릅니다. 초기 스냅샷과 복구 기준 준비가 끝날 때까지 기다립니다.
⑨ 적용 결과의 오류 유무, 지정된 폴더 경로, 복구 기준 준비 여부를 확인합니다.
   중요한 원본 문서 전체를 첫 시험 대상으로 선택하지 않습니다.
   버튼이 비활성이라면 동의 체크·변경 여부·진행 중 작업·검토 보류 메시지를 확인합니다.
   차단 이유를 무시하거나 관련 DB를 직접 삭제하지 않습니다.

수동 복구 확인 — 무해한 문서만 사용
① 설정 → '스냅샷 관리' 탭으로 이동합니다.
② '수동 스냅샷 생성'을 누릅니다.
③ 완료 후 목록에 새 생성 시각과 ID가 나타나는지 확인합니다.
   클릭만으로 성공으로 판단하지 말고 오류가 없는지 확인하세요.
④ 메모장에서 복구시험.txt를 열어 '수정된 내용입니다'로 바꾸고 저장한 뒤 닫습니다.
⑤ 방금 만든 스냅샷 행의 '복구' 버튼을 누릅니다.
⑥ 미리보기에 나온 대상 폴더와 파일 목록을 확인한 뒤 덮어쓰기에 동의하여 실행합니다.
⑦ 복구 결과를 확인하고 문서를 다시 열어 '복구 전 원본입니다'로 돌아왔는지 확인합니다.
   이 기능은 지정 폴더의 대상 파일을 복구하며 Windows 전체를 되돌리지 않습니다.
   수동 복구 성공은 실제 랜섬웨어 자동 탐지·종료·격리 성공과 별개의 결과입니다.

콘솔 및 재부팅 확인
① 설정 → '진단 및 로그'에서 커널 수집·탐지 판단·대응 복구 콘솔을 각각 열어봅니다.
② 사건이 없으면 탐지·복구 출력이 없을 수 있습니다. 정상 프로세스 이벤트는 위협과 다릅니다.
③ 창을 X로 닫은 뒤에도 대시보드 엔진 연결 상태가 유지되는지 확인합니다.
④ 열어둔 문서를 저장하고 Windows를 '다시 시작'합니다.
⑤ 로그인 후 대시보드·수집기가 복귀하는지, API 키 등록 상태와 복구 폴더가 유지되는지 확인합니다.
   UI가 안 열리면 Ransom0 바로가기 → 관리 창 '실행'으로 상태를 확인합니다.
   수동 실행은 성공했더라도 자동 복귀까지 성공했다고 기록하면 안 됩니다.

5. 제거와 원래 보안 설정 복원
① 설치 관리 창의 '제거'를 사용합니다. 보류 사건이 있으면 먼저 원인을 확인합니다.
② 제거 완료를 확인하고 요청된 재부팅을 마칩니다.
③ 관리자 PowerShell에서 다음을 실행합니다.

    bcdedit /set testsigning off

④ 성공 메시지를 확인하고 Windows를 재부팅합니다.
⑤ UEFI 펌웨어 설정에서 Secure Boot를 원래 상태로 복원합니다.
⑥ Windows 정상 부팅 후 관리자 PowerShell에서 확인합니다.

    Confirm-SecureBootUEFI
    bcdedit /enum "{current}"

원래 Secure Boot가 켜져 있었다면 첫 결과는 True여야 합니다.
testsigning은 No 또는 항목 없음인지 확인합니다. Yes가 남았다면 설정을 다시 확인합니다.
⑦ 일시 중단했던 BitLocker 보호를 재개합니다.
제거는 기존 네트워크 정책까지 자동 초기화하지 않습니다. 별도로 바뀐 정책이 있다면
시험 전 백업·변경 내역과 비교해 필요한 항목만 복원합니다. 모든 방화벽 규칙을 지우지 않습니다.

6. 오류 및 시험 기록
오류가 나면 확인할 곳
- bcdedit: '액세스가 거부되었습니다' → 관리자 PowerShell인지 확인합니다.
- bcdedit: 'Secure Boot 정책으로 보호' → 해당 Windows의 Secure Boot 설정을 확인합니다.
- Confirm-SecureBootUEFI: '지원되지 않음' → UEFI인지 확인합니다. BIOS 전환을 임의로 하지 않습니다.
- 설치: 시험 서명/보안 부팅 조건 오류 → 설정 후 재부팅했는지, False/Yes를 다시 확인합니다.
- 설치: altitude 충돌/드라이버 로드 오류 → 오류 문장을 보존합니다. 다른 드라이버를 임의 삭제하지 않습니다.
- 설치: VSS 비활성/용량 부족 → 표시된 원인을 먼저 해결합니다. 기존 보호 스냅샷을 무작정 지우지 않습니다.
- Windows 메모리 무결성·Defender 등은 일괄적으로 끄지 않습니다. 서명·호환성 오류를 먼저 확인합니다.
- BitLocker 복구 화면 → 미리 보관한 복구 키를 사용합니다. TPM 초기화나 디스크 초기화를 하지 않습니다.

자동화에 관해
시험 서명 명령·검사는 관리자 도구로 자동화할 수 있지만 현재 설치본은 변경하지 않습니다.
물리 PC Secure Boot 설정은 제조사·펌웨어·관리 정책에 따라 달라 공통 명령으로 보장할 수 없습니다.
두 환경의 시험 준비가 끝났더라도 Microsoft 정식 배포판이 된 것은 아닙니다.
