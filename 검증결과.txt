Ransom0 Preview18 검증 결과

수정 사항
- 새 복구 범위를 적용할 때 예약 주기 대기 때문에 과거의 빈 스냅샷을 재사용하던 문제 수정. 실제 새 스냅샷을 지정해 복구 목록 작성.
- 커널 원본 이벤트를 기존 콘솔 표시 옵션과 독립적으로 전달.
- 여러 백엔드 출력 연결 중 유휴 연결이 다른 연결을 막던 문제 수정. 새 출력이 없으면 대기 안내 표시.
- 예약 백그라운드 작업은 pythonw.exe로 실행하여 콘솔 창 노출 방지.
- 업그레이드 준비 시 콘솔 의존 모듈을 함께 배치.
- TestLab 단일 인자 잘림 수정 유지. 제품 복구 범위는 12개 문서를 요구하지 않음.

통과
- 백엔드 512개, 설치기 19개, TestLab 7개 자동 시험.
- Windows 11 VM 기존 설치 업그레이드 완료. 네트워크·계정 설정 비교 동일.
- 기존 파일 1개(5바이트)로 새 복구 기준 준비 완료. 실제 VSS 파일 및 임시 복사본 SHA256 일치. 사용자 원본 미변경.
- 실제 새 커널 이벤트 5개가 원본 출력 파이프로 전달됨.
- 대응 출력 동시 파이프 전달 검증. 대응 사건을 위조하거나 성공 건수에 추가하지 않음.
- 커널 유실·큐 비움 모두 0, 카운터 초기화 없음.
- 375개 payload 파일 무결성, 설치 번들 검사 및 비밀정보 패턴 검사 통과.

한계 및 시험 중 문제
- Preview17 후보 업그레이드의 콘솔 의존 파일 누락으로 분석 작업이 실패했다. 원본 수집 프로세스는 유지했고 작업을 복구한 뒤 Preview18로 업그레이드했다. 후보17은 배포하지 않았다.
- VM 일시 중지 중 원격 검증 요청이 시간 초과했다. 재개 후 실제 생성 상태와 VSS 파일을 확인했다.
- 이번 버전의 신규 설치·재부팅, 물리 PC, 타 백신 공존, 실제 JEV 강제 종료·복구 전체 흐름은 이번 시험 범위가 아니다.
- 콘솔 파이프 및 예약 작업 실행 파일을 검증했으며 모든 UI 버튼을 수동 클릭한 시각 검증 결과는 아니다.
- 어떤 부하에서도 유실 0이라고 보장하지 않는다.

이벤트 원인 비교: 검증 에이전트 실행 중 30초 UI 기록 289건(9.62/초), 중지 후 30초 48건(1.60/초). 전자는 vmtoolsd 로그와 반복 프로세스 생성·종료가 주된 추가 기록이었다. 검증 에이전트만 중지했고 수집기 PID는 유지, 마지막 유실·큐 비움 0. 짧은 관찰값이며 일반 성능 보장이 아니다. 제품의 정상 이벤트를 추가로 제외하지 않았다.
